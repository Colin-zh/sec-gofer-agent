## 窗口必须有锚点与边界

| 需求 | 计算口径 |
|---|---|
| 截至D含当天最近N个自然日 | 日期范围 `[D-(N-1)天, D]`；时间戳范围 `[当天起点-(N-1)日, D的次日起点)` |
| 截至T最近H个经过小时 | 例如 `[T-H小时, T]`，端点是否包含由需求确定 |
| 过去M个日历月 | 按日历偏移，不等于固定天数；月底截断行为需要约定 |
| 任意连续N天最大值 | 滚动窗口并找最大结果，不是只在截止日评估一次 |
| 事件后L时间内匹配 | 相对每个事件的范围，需明确是否允许相同时间戳 |

N必须为正整数；小时跨度必须有效且为正。截止日不是自动使用 `event_time.max()`：显式评估锚点与末次观察日期可能不同。若契约选择末次事件锚点，要说明并处理无事件组。

自然日时间戳过滤使用次日起点的半开区间，避免用午夜作为截止时刻遗漏全天事件，也避免使用“23:59:59”遗漏更高精度记录。对每实体锚点不同的输入，需验证组内锚点唯一。

## 基线与监测期

先计算监测区间 `[monitor_start, monitor_end)`，再计算紧邻其前的基线 `[monitor_start-baseline_length, monitor_start)`。不要只有 `t < monitor_start` 而遗漏基线下界。

相对“前N个有事件时间桶”和“前N个自然日”不同；无事件桶是否补齐需要明确。

## 时间类型与排序

- 日期与时刻分列时组合完整时间戳，验证时刻范围，不将缺失时间填零后当作真实先后。
- 明确源时区、分析时区。当地自然日先转分析时区再取日期；精确经过时间可在统一时区计算。
- 夏令时导致一天未必24小时。日历边界采用日历偏移，经过时间采用 Timedelta。
- 保留需求所需精度。优先使用 datetime/Timedelta 差值；不要先转换整数秒丢弃微秒。
- 同时间戳不证明先后。可选择拒绝歧义、排除同刻匹配，或用有业务顺序含义的序号；任意字符串ID排序只能提供确定性，不能证明事件先后。
- 缺失时间不能通过取反窗口掩码自动归为历史记录。

## 覆盖、尾部截断与未来信息

把目标事件范围与支持事件范围分开。例如只评估 `[start,end)` 中的起始事件，若每个起始事件需观察后续L小时，支持数据应覆盖到 `end+L`，但分母仍只含目标起始事件。

不能为修复尾部漏配把所有后续事件也纳入目标分母。缺少支持数据时报告未观察完整的事件数，按契约返回未知或仅计算完整观察子集，不把未观察当作未命中。

数据覆盖应由数据源元信息、采集状态或日历覆盖保证提供；首条事件晚于起点不证明缺数据，首条事件早于起点也不证明期间完整。

历史评估要区分事件发生时间、资料生效时间和资料获知时间。若要求当时可知结果，不能使用后来获知的身份关系，即使它的生效日早于事件。

速率分母可为精确跨度、有效事件日数或已知完整观察期长度；不能只为避免除零默默改为1。见 [时间指标](execute-metrics-time.md)。
