## 最小口径契约

生成代码前明确下列会影响结果的项目；简单映射只需涉及相关项。

| 项目 | 需要确认 |
|---|---|
| 输入与输出 | 每行表示什么；结果每行表示什么；是否保留没有事件的实体 |
| 身份键 | entity_id、account_id、event_id各自唯一性范围；不同系统是否需要复合键或映射 |
| 取值语义 | 类别编码、方向、单位、有效期、数据来源；字段描述为空时不能按名字猜测 |
| 统计范围 | 全部输入还是窗口；截止锚点、分区与排序键 |
| 聚合 | 分类别统计/合并/净额；计数记录、去重实体或账户；先去重还是先聚合 |
| 判定 | 分子分母、比较符号、任一/全部、最小样本量（如有） |
| 质量 | 缺失、非法值、零分母、空输入、无事件和全缺失组的行为 |

定义来源优先采用用户确认、数据字典及项目实现；发生冲突时显式指出并确认，不以样例推翻字段契约。样例用于核验，不足以证明整列完整或唯一。

## 四种生成模式

1. **精确实现**：字段与规则齐全，代码计算原始指标。
2. **代理实现**：可观测字段近似原指标。说明原义、替代字段含义、偏差、适用人群/限制；需要授权。使用 `*_proxy` 等不误导的输出名，不能仅换字段还声称精确实现。
3. **扩展字段模板**：算法可确定而资料未接入。声明假设输入字段及构建方式；字段不存在时显式失败，不能自动用别的字段填补。能否实际运行取决于契约是否满足。
4. **子指标实现**：整体结论无法精确定义，输出可解释的观测指标，不自行加入阈值或合成最终标签。

可以组合模式，例如精确计数加代理类别。逐个输出说明模式，避免整项写“已实现”掩盖仅实现部分。确实无法建立口径时标为待确认，说明阻塞条件，不制造无意义代码占位。

## 扩展字段应声明什么

- 字段名、类型、单位、允许值、缺失含义和标识作用域。
- 来源表与粒度、连接键、预期基数、重复记录处理。
- 快照截止日或生效/失效区间；聚合列表的来源与去重方式。
- 身份映射是否覆盖外部实体；覆盖不足如何报告。
- `None` 表示未知还是无记录；列表 `[]` 只有确认无关系时才能代表空集合。

例：事件归属模板要求 `event_id:str`、`entity_id:str`、`event_time:datetime`、`value:double`；事件ID在指定数据域唯一。资料缺失不能用名称相同推断身份相同。

## 空值与数据质量

缺失不等于零或False。完整事件表中实体无事件可计0，但缺表/覆盖未知不能这样处理。全缺失数值的 `sum()` 默认结果可能为0，需要按契约使用 `min_count`、空值或报错。

默认不静默执行 `errors="coerce"`、`fillna(0)` 或丢弃非法行。采用用户确认的容错模式时区分缺失与解析失败，并报告排除数量及对分母的影响；日志/错误信息不要暴露完整敏感记录。

## 口径更新

记录确认值、来源与作用范围。用户更正计数对象、窗口或代理策略时，重算相关输出、说明和测试；不能只更新后续条目。既有授权仅在相同语义范围内复用。
